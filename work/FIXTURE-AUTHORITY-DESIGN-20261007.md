# Independent authority for generated fixtures (GPT-6 row H item 3; DEPUTY-KERNEL, 2026-10-07)

## The hole (read at main 4ef4e808)
`Assurance/NativeAcceptedFixture.lean` re-runs the op-2 admission in Lean over a recorded Store prefix and checks
(`first_accepted`) that the accepted intent's record is byte-for-byte the record the native Host appended, and the root
the Host's. `scripts/native-accepted-fixture/generate.sh` writes `NativeAcceptedFixtureData.lean` from a fresh world run
by binaries built FROM THE SAME TREE. Its hard-coded asserts pin only the VERDICTS (first ACCEPTED, record=same, r01
REFUSED with the Host's reason). The bytes it pins (`firstRecordHex`, `firstWorldRoot`, the prefix) come from the
implementation under test. The merge keeper regenerated it in c14, n3 and n4 at batch tips: any change to WHAT an
accepted invocation records (a dropped field, a changed effect, a wrong fee) is absorbed by regeneration. The test then
checks only that the compiled Host and the Lean evaluation of the same code agree.

## Design: generated bytes may change; what they MEAN may not, without an authority change
1. **Authority file per fixture**, e.g. `Assurance/NativeAcceptedFixture.expect.json`. Hand-written, owned by a reviewer,
   NEVER written by any generator. It states the semantic projection of the fixture, derived from the acceptance driver's
   INTENT (what the call asked for), not from the run:
   - per call: verdict (accepted / refused + refusal NAME);
   - for an accepted call: the decoded record's projection: transaction kind/op, target cell ids and roles, the method, the
     effects (cells written, by kind), the fee posted (by the tariff formula from the pinned config, computed by the
     authority from its inputs), the signer set (keys by role), the nullifiers consumed (count/kind);
   - the invariants a regeneration must keep (e.g. the number of verified triples, the record height).
2. **Projection in Lean, checked both ways**:
   - `def project : IntentRecord → Projection` (pure, small, in the fixture module);
   - `theorem first_projection : firstRun.map (project ∘ record) = some expected` where `expected` is decoded from the
     authority file by `include_str`. Compiled evaluation, as the existing theorems are.
   - `generate.sh` computes the same projection and REFUSES to write data whose projection differs from the authority
     file, printing the field-by-field diff. It never touches the authority file.
3. **Authority changes are separate, reviewed commits.** A gate row (`fixture-authority`, in merge-gate-checks.sh) over the
   batch range fails if any single commit changes BOTH an authority file and implementation sources (Kernel/, Compiler/,
   Host/, native/). An authority change must be its own commit carrying an `Authority-Change: <reason>` trailer, and the
   keeper logs it as a semantic change, so the keeper's "regenerated" LOG line becomes "regenerated, projection unchanged"
   or names the authority commit.
4. **Plants (the gate must go red)**: (a) a Kernel change that drops a field from the accepted record, then regenerated:
   `first_projection` and generate.sh both refuse; (b) one commit changing implementation + authority together: the
   fixture-authority row goes red; (c) the authority file edited to the WRONG verdict: `first_projection` goes red.
5. **Generalise**: the same three parts (authority file, projection theorem, separate-commit gate) for every generated
   fixture the keeper regenerates at batch tips. Census: `git log --format= --name-only` over the LOG's fix-forward commits
   for `*Fixture*`, `*fixture*`, `TallyTwelve.core.json`, `tests/**/expected*`; list each with its generator in a committed
   `scripts/pipeline/fixture-authorities.txt`, and have the gate refuse a generated file that has no authority row.

## Not in scope
Independence of the Lean replay from the Host binary (both are this tree's Lean; the transcript gate covers the verifier
process). That is evidence class "differential", and the projection does not claim more.
