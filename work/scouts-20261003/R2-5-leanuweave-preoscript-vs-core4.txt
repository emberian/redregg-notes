WHAT IT IS
/Users/ember/dev/leanuweave (public emberian/lean-uwueave, branch dev, clean at f145066 "sweep-up commit from usage wall", 2026-08-14, nothing since) is a Lean-core library (no mathlib, Lean 4.30.0) answering one question: can a promise about replicated state be kept without coordination? When no, it gives a two-replica counterexample and a priced list of repairs [READ]. 166 commits, 515 .lean files, ~111.7k lines under Uwueave/, ~28.9k lines of Rust in rust/ (a host that runs Lean→C kernels and adds journals and authenticated admission) [READ]. README reports 185 modules and 25,747 audited constants [RECORD].
PREOSCRIPT (Uwueave/Preo/, ~60 files; PREOSCRIPTING.md 1,345 lines) = a language for declaring contracts, implemented as Lean commands at elaboration time: preo, preo_program, preo_certificate, preo_protocol, preo_plan, preo_budget, preo_export_v3 [READ]. Fields/invariants/derived values elaborate into kernel-checked verdict terms. Small typed query language Preo/Expr.lean (Term, 17 constructors: Bool, Nat, pairs, options, field refs, custom escape hatch). Results = future-indexed evidence (Preo/Future.lean: WorldModel, FutureDecl, CheckedCertificate) with six statuses (StatusEffects.lean). Coordination costed as a profile over strategies composing pointwise (CoordEffect.lean), five currencies (Scheduling.lean). Budgets have three outcomes (Budget.lean): lower bound can reject, only a witnessed plan can accept, else "unresolved". Output = canonical first-order artifacts (V1/V2/V3 projections) renderable to Rust as data [READ]. It is a contract/judgement language about promises under concurrency, NOT a general-purpose language. Its own §11 names when to abandon it: "If the deep-embedded core cannot stay under roughly a dozen constructors… the right answer is a tactic library plus a code generator". Expr.Term now has 17 [READ].

RELATION TO OBJECTIVE BEND CORE4
Orthogonal layers with one real point of contact. Not the same thing; not a predecessor Core4 absorbed. Core4 = the object/computation calculus (lam/app, mix, fix, specification, prototype, reflect, lazy records, ifZero; no Bool eliminator, no sums, no effects, no merge, no futures). Preoscript = a calculus of promises about replicated results (invariants, futures, status, coordination obligations; nothing about inheritance/self/super/open recursion). None of C1–C27 is about concurrency/futures/merge; Preoscript has no fix/mix; overlap empty at the constructor level. THE POINT OF CONTACT: Core4's weak spots C14 (laws separate from authority — PART; "source laws undischarged callables"), C1/move 4 (check requires at compose/fix), C16 (Plan as data): exactly where Preoscript's evidence types belong. Preoscript is a CONTRACT LANGUAGE CORE4 SPECS SHOULD CARRY AND CHECK, not a projection target to emit (emitting V2/V3 rows from Core4 would recreate the dead-fixture edge). Structural rhyme [INFERRED]: CoordEffect's "compose profiles pointwise, choose the strategy once when the session closes" lines up with "mix composes open specs; fix closes them"; obligations could compose at mix and be minimized at fix. Catch: an ordered override can DELETE an obligation, so a mix's profile is not simply the sum — a theorem is needed, not an alias.
