1. TRAFFIC PRIVACY
STATED (WHY-TRAFFIC-PRIVACY-20261003.txt 18–29): "hide association of an honest client contribution with an honest output among at least two compatible honest contributions". Adversary sees all links, controls other clients and some relays, can inject/tag/replay/withhold/drain. Premises: ≥1 honest whole-batch shuffle; honest non-colluding registrar; honest receiver; private endpoint keys; corruption set fixed during the run. Not covered: later key compromise, adaptive corruption, cross-cohort linking over time. Public by design: cohort membership, presence, IP, reservation class, packet bounds, epoch, lifetime, faults. The end Host sees the full author and object graph (13–16). Same restricted profile = "P1" in PRIVACY-COMPOSITION-REVIEW 79–89.
IMPLEMENTED (all Rust; no Lean model of the mix): hbox:/tank/dregg-build/codex-traffic-20261003/native/resource-client/src/{pq_mailbox.rs (2010 lines), cohort_tcp.rs, scheduled_transport.rs}, PQ-MAILBOX.md. Four-layer onion: ML-KEM-768 + XChaCha20Poly1305 via AWS-LC, +1,160 bytes/layer; route registrar → 3 relays → mailbox receiver. Fixed public cohort; each client sends exactly one equal-size packet per epoch, dummy or real; epoch classes rotate app/app/control/repair. Replies: receiver broadcasts the same W ciphertexts to every client; each opens its own with a one-time capability; no SURBs. Active guard: registrar publishes sorted hash sets for all five packet stages; each operator refuses the whole epoch if anything is added/dropped/duplicated.
WHAT v12 ACTUALLY CHECKS (native/resource-client/cohort-native-tcp.py; evidence traffic-tcp-native-evidence-v12/{all-cover,native-delayed}/public-run-summary.json, receiving.log): W=4, P=4096, T=1000 ms, G=2, N=64. EVERY ROLE RUNS ON 127.0.0.1 ON hbox. The "observer" = byte-transparent localhost TCP proxies logging (link, phase, slot, epoch, bytes, relative_ms). Assertions: 12·N = 768 records; every record within 100 ms of schedule; every client receives a valid identical broadcast every epoch; exactly 16 source submissions; exact expected outcome bytes; the shape tuple (link, phase, slot, epoch, bytes) identical between the all-cover pole and the native-delayed pole. Timing never compared between poles beyond the 100 ms tolerance; the max-lateness figures (2.276/2.256 ms) are reported, not asserted. The "16/16 useful outcomes" are THE SAME SINGLE HISTORICAL READ-ONLY REQUEST (request.native) resubmitted every 8 epochs by 2 clients ("Historical lookup is read-only") — not 16 distinct new effects.
GAP: no observation-game proof (the reduction "is a cryptographic composition proof obligation", PQ-MAILBOX.md); no live authenticated enrollment (registrar adapter reads CSV paths); roles share one machine ("independent keys and guard checks do not manufacture independent administration or noncollusion", WHY 54–55); v11 showed private native I/O contention disturbing relay readiness; v12 passing "is not a proof that this is secret-independent under arbitrary contention" (78–84); a corrupt downstream relay still sees intermediate unavailability records; the agreement carrier R3 replayed an ALREADY-INSTALLED room birth, so "no first new private effect" has been carried (SCENARIO-PRIVATE-AGREEMENT 39–43); the endpoint sees the clear call and result (no private execution behind the mix).
ASSUMPTIONS: trust — the registrar is substantial, not decorative. Faults — corruption fixed for the run; one malicious enrolled member can abort an epoch without being identified. Lifetime — a fixed 64-epoch run; rollback of keys/capabilities voids privacy. Capacity — W=4, anonymity set ≤4, public presence alone can shrink it. Cost — P·(W²+5W)+17237·W+1016 bytes per epoch ≈ 66 GB per client per 30 days at W4/P4096; broadcast O(W²·P). Latency — 10 s contribution→broadcast. Not PQ end to end: native signatures are Ed25519.
BLIND SPOT (INFERRED): "768/768, 16/16, ≤2.276 ms" shows one machine kept a cover schedule while repeatedly replaying a read-only lookup — evidence about schedule shape and exactly-once delivery, not anonymity against anyone who can see the registrar or the co-located processes.

2. AGREEMENT ("four-source")
STATED (WHY-AGREEMENT-20261003.txt): Generic Simplex 1/3-VA (arXiv 2609.32985). Model: fixed membership; Byzantine faults with corruption set fixed; n=3f+1, q=2f+1; authenticated reliable channels; unknown GST with known Δ afterwards; timeout ≥7Δ. Six separate obligations: delivery, ordering, validity, installation, custody, release. "Meaningful" also = joint turns across independently governed domains (all required YES → Commit, any NO → Abort, designated final signer d*), plus epoch close and transfer of old certificates. Human requirement: "some kinda consensus/agreement" for the alpha (OCT13-OBJECTIVE-RECOVERY R[6996]).
IMPLEMENTED: engine = Lean executable engine compiled native (Kernel/GenericSimplex*.lean, Compiler/GenericSimplex{Codec,IO,Native,Participant,Pending}.lean) with real TCP, MAC, ML-DSA-65, durable journals. Deployment: four logical participants and four physical source stores ALL ON hbox, initialised from the same seed ("not four independently deployed failure domains"). Proof (hbox:/home/hbox/workbox/codex-simplex-proof-20261003/src/Kernel/GenericSimplexEngineSafety.lean): actual_committed_prefix_consistency holds for any network reachable from the real executable start/step assuming parties = 3*faults+1 and faulty.card ≤ faults: committed blocks are prefix-comparable; actual_certified_next_record_unique: unique next record after a shared source prefix; authentication assumed inside AllowedInput; signature unforgeability abstract. A genuine SAFETY theorem about the Lean model; nothing about liveness. Native signature-origin and receiver-attribution are separate open joins (protocol-global-receive). Runtime record (codex-agreement-20261003/RESUME-CURRENT.txt; protocol.json row protocol-agreed-workdesk): room birth fdfc installed once on all four stores; document birth 92a07 installed (count 2) in 124 s; four fresh reader PROCESSES returned byte-identical receipt 0c9684e5; INITIALIZATION 00f711 TIMED OUT AT 180 s AND READS ABSENT — journals hold only 2 of the 3 COMMIT witnesses needed at view 17; replaying a known call 59.8 s cold / 2.1 s warm; session broker activated 19:15Z, retry of the same init pending. WHAT KIND (INFERRED): partially synchronous BFT state-machine replication for ONE governance domain of 4 replicas. Not a cross-domain joint turn in the Bread sense. "Four independent native readers" = four stores agree on what they read back; not four operators. Byzantine behaviour exercised only by harness schedules (selective COMMIT delivery, tampering, stale CAS, restart).
MEETS WHY-AGREEMENT? Partially: ordering, validity (historical replay), installation, for ordinary public operations in one domain with crash/restart/lost-reply recovery. NOT met: custody, release, private or joint operations; dynamic membership and epoch close; fairness and censorship resistance; observed liveness (the third operation is stuck).
ASSUMPTIONS: faults f=1 of 4, corruption fixed; one hbox failure takes out all four replicas. Trust: no rollback of signer storage. Lifetime: no checkpointing/GC; full history in each CAS. Capacity: ~1 op per 2 min cold; 16 MiB frame limit bounds journal reads. Cost: five all-to-all full-value waves, ~5.05 MB per instance at n=16 with a 4,160-byte value.
BLIND SPOT: "four independent… agreeing" reads as four failure domains but means four processes on one host; "installed count 2" read as working agreement while the next operation is stalled.
