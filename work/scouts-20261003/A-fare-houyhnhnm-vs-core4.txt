FIVE THINGS THAT MATTER MOST
1. Booleans have no eliminator. The only branching constructor is ifZero on a Nat, so a == b can never drive control flow. The parser accepts || < <= > >= - / !=, but the elaborator lowers only + * == && [R objective-elaborate.ts:191-192].
2. Composition is mixin-only. compose(a,b,c) is a left fold of mix. No dependency DAG, no linearization, no identity. By Faré's ranking (ltuo §11.1.8) mixin inheritance sits third, below the two flavorful multiple-inheritance forms [R].
3. Spec requirements are not checked. `requires` survives only as a JSON string inside the metadata label. Laws are callable values; nothing discharges them [R objective-elaborate.ts, spec branch].
4. The whole package is one lazy fixpoint, but nothing can extend it. Root is fix(λself.λsuper. record(all declarations), {}). That is Faré's "global fixed point of the namespace"; EvenOdd works through it. But the root ignores super and is not a specification, so another package cannot extend the ecosystem [R].
5. Several live claims in OBJECTIVE-BEND.md rest on Gen-1 code. "Pinned instance births and kind evolution" go through Compiler/ObjectiveBendInstance → ObjectiveBendElaboration → BendCoreAdmission → BendTT [R imports]. The linked persistence contract serializes Theory/BendClosureMachine.State (old strict machine), not the Core4 demand machine [R].

FIVE MOST VALUABLE MATURATION MOVES, RANKED [I]
1. Sums with case (gives Boolean branch). Needed for C16 (Plan as sum of actions), C17, C7 (lists for linearization), C8 (sub-method lists). Cost: 2–3 constructors (inject label term; case term [(label, body)]; if = two-arm case); one new machine frame (case, carrying environment); new Value/RuntimeValue case; new preservation case. Type system: sum/variant row type with exhaustive-case typing, reusing row machinery. Unblocks the most downstream work per constructor.
2. A Core4 activity: effects as yield, plus a checkpoint codec (fci §5.2; persist-model; contract 4; BEND-PERSISTENT-COMPUTATION's purpose). Cost: one constructor (perform plan), one Control.yielded state with a resume rule injecting the response into the saved stack; State already first-order so codec needs no constructors. Typing needs a decision on Comp-vs-judgment and on effects inside shared thunks (open council question). Machine adequacy needs a yield case.
3. Declared ancestry with ordered C4 linearization and method combination at elaboration time (poof §4.3; ltuo §7.3–7.4, §9.2; scholar's ordered-presentation theorem). Cost: zero core constructors if static DAG; elaborator computes order and emits mix chain + effective-method wrappers; generative identity static. Needs its own theorem (ordered-presentation invariance, suffix soundness). First-class later needs move 1 + label equality.
4. Check `requires`, and close final-self assumptions, at compose/fix (ltuo §8.2; WHY; scholar §7). Cost: no constructors; new typing rules (required row checked against composed provided row at fix; width-subtyping or row-extension rules). Metatheory-only; makes partial specifications into checked collaborations.
5. An extensible package root, label equality and a dynamic get (ltuo §9.3.7, §9.2.9; ch07). Root as specification: elaboration only. Label equality: a primitive. Dynamic get: 1 constructor + frame variant. Makes "extend what you do not own" true.
Deferred: consumed-mark for linear values (council T5): high-stakes, no consumer until move 2.

EFFICIENCY AND COMPILERS: CONSTRAINTS ON THE OO DESIGN
- Static dispatch is staged OO (ltuo §9.4.4.2); sealed/final/suffix reduce dynamic to static (§9.4.4.1); suffix fields get constant offsets (§10.4.2). Backend requirement [I]: a statically recognizable sealed/static fragment (composition, selector names, field layout known at elaboration). The current Objective numeric compiler already works this way (normalizes fix/beta away over an all-Nat module [REC BEND-LOGIC-COMPILATION L17–22]). Moves 3 and 4 fit; move 5's dynamic get must be marked outside the fragment.
- Laziness vs oblivious execution: thunk forcing order and cache state are data-dependent and leak via access pattern/timing [I]. "Branching on a secret requires oblivious execution or an authorized disclosure. Evaluating both effectful branches and choosing afterward is unsound" [REC GRADED-EXECUTION L431–433]; "Inconsistent: strictly no timing/termination leakage AND unconstrained observable secret-dependent completion; add a public bound/padded schedule or allow leakage" [REC L573–574]. Council-2 §4: a clocked strict CPS backend covers only the strict fragment; T1 shows CBV approximants incomplete on productive targets. So sums/case must have a both-arms/mux lowering, and an effect must never execute inside a forced shared thunk.
- Public resource vector: "Termination does not supply a public resource bound or private access pattern" [REC BEND-DIRECTION L75]. Council-2 suggests a vector of fix-unfoldings, steps, allocations, heap, stack; DemandMachine.Limits + ticks already has that shape. Canonical gas "cannot be the number of backend physical instructions" [REC BEND-WORLD-LANGUAGE L73].
- Arithmetic domains: source Nat unbounded; native/circuit backends need a proved bounded domain with fail-stop, never silent wrapping [REC BEND-WORLD-LANGUAGE L75; BEND-LOGIC-COMPILATION "integer no-wrap"].
- Reflection limits optimization: "Every exposed observer constrains valid optimizations" (WHY). Decide the observability contract (C12) before adding reflection constructors.
- Representation choices: defunctionalized closures in tables and total first-order interpreters remain valid lowerings if they faithfully represent suspensions, environments and effects; they are not source restrictions (WHY [E2]; scholar §2).
