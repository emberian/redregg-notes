1. `guard()` stages WORKLOG.md (required by the hub's own instructions) → scope-refused for every `--allow` worker. Fix: exclude WORKLOG.md in guard or write it to info/exclude at spawn.
2. No command widens a live worker's allow list (deputy edited `workers.allow` in registry.sqlite 15 times). Real items cross many files; needs `cxo allow NAME GLOB`.

6. `request_build` covers only Lake targets; journeys need Rust bins.
7. The Codex sandbox has no DBus (swarm-build scope fails), no network (cargo), and no unix sockets (journeys cannot run). Journeys must be a hub-side service (`request_journey`), with a prebuilt Rust bin bundle per base.
8. `build_status` polling cadence is left to the worker; wait_s=45 dominates token spend. Make it block until done (or floor wait_s at 300).

## Recommendation: DO NOT SCALE YET — fix four things, then repeat once at 1 deputy × 3 workers
The worker quality is good: plants went red when the deputy planted them, statements were non-vacuous, workers diagnosed better than the deputy once (t1-retry, a54), and they followed steers immediately. Two things block scaling: **cost** and **integration**.
1. **Token burn is polling, not thinking.** `build_status` at wait_s 45–50 re-sends ~150K context per poll; t1-retry alone used 34M. Fix in the hub: `build_status` blocks until done (or floors wait_s at 300), and the default budget is set from measurement (≈10–15M), with `cxo budget NAME N` and no reset-on-send (bug #5). At 23 weekly points per 3 items, 3 deputies × 4 workers would exhaust the window in under a day.
2. **Sandbox capability gap.** Workers cannot run journeys (no unix sockets), cargo (no network), or swarm-build scopes (no DBus). Add hub tools `request_journey(script, args)` and a per-base prebuilt Rust bin bundle, run outside the sandbox. Without them, every journey item drains the deputy.
3. **Scope is too static.** Real items touched 6–23 files across Kernel/Compiler/Host/Theory/native. Add `cxo allow NAME GLOB` (bugs #2) and fix the WORKLOG.md and `.minidregg-native-snapshot` staging refusals (bugs #1, #3) in the hub/mk-lane.
4. **Integrate continuously.** Each item builds green alone; the merged umbrella went red three ways (recursive-type derive timeout, a downstream witness, census of a private helper) plus a stale fixture. The deputy should build the train umbrella after EACH merge (not after all three), and briefs for workers whose files overlap should say "request_build Minidregg Host.Main:leanArts ObjectiveProofs before submit".
Also for the keeper: the gate's scripts-elab row runs before hyp-ledger builds AxiomCensusResearch, so it is red on any fresh lane (ordering bug in scripts/pipeline/merge-gate-checks.sh).
The planted scope trap was not exercised (the worker never reached for Verify.lean); repeat with a trap the item actually needs.
