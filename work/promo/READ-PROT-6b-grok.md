## (1) The blocker

Confirmed. A method cannot build a nested invoke's arguments from a value it computed. It can forward bytes it already holds.

[READ `Lang/Package.lean:114–115`] the `invoke` arm of `callArms` is `("args", .bytes)`. [READ `Lang/Call.lean:162–164`] `bodyOf` reads that field with `bytesAt`; anything else is `"args: not bytes"`. [READ `Lang/Term.lean:17–26`] `Prim` is `add sub mul div mod eq lt le beq cat deq lenLe`. [READ `:44–70`] `Term` has `nat`, `bytes`, `record`, `get`, and no constructor that turns a term into bytes. `cat` concatenates bytes. `digest` is a literal, "never made from bytes at run time" (`:52–54`). There is no encoder a method can call.

[READ `decisions/lang.md:374–375`] LANG-23 (iii), word for word: "a nested invoke's `args` are bytes. Until ID-4's bytes primitives, a method forwards only bytes it already holds." It is an escrow gap sent to LEDGER (`:368`), not a LANG build item. [READ `:393`] LANG-23's status is "built" with LANG-33's declared slots. That amendment did not touch (iii). [READ `:736–737`] the consumer that landed with it, the Relay, "forwarding pre-encoded arguments (LANG-23 (iii))". [READ `Lang/Journey.lean:285–300`] `go` puts `rest` into the invoke's `args`. `rest` is a `bytes` field of the arguments the signer supplied. The Relay never computes a call.

Why (iii) is still open: the sentence that was supposed to close it named the wrong event. [READ `decisions/lang.md:2677`, `:2771`] LANG-64 is ID-4, and it landed `cat` / `beq` / `deq` / `lenLe` as a tick price. `len` / `take` / `drop` were refused because no package needed them. No `Term` encoder was in that card. The wire codec already encodes. [READ `Lang/Wire/Data.lean:126–131`] `encodeData (T : Ty) (d : Data) : Option ByteArray`, and `decodeData` beside it. [READ `Lang/Program.lean:401`] entry uses `decodeData` on the call's argument bytes. [READ `:459`] exit uses `callsOf`, which demands those bytes already. The asymmetry is the whole gap: a method receives decoded data, and can only send bytes.

Worth naming to Ember, in one sentence. Nano's open composition (LANG-21/23: a method returns calls as data) cannot compose a call from a value it computed. It forwards bytes, or literals, or `cat` of those. The Relay is the existence proof of the limit, not a counterexample to it. `encodeData` sitting on the other side of `callsOf` is why the limit looks like an omission and not like a missing codec.

L is that limit, hit. X decodes θ, judges it, and cannot hand Y the θ it judged. Forwarding some other byte string the signer supplied is a second θ, and nothing in the term language checks that the bytes are the value. That is the §0.6 failure, and it is real.
