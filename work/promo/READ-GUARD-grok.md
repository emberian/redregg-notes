## (2) The declared map

Two different claims, and the card checks only one of them.

`RENAMES: old → new` compares. [READ §3.2, §3.5] The map is applied to the candidate side (longest component-wise prefix, so generated children follow the owner) and inverted, so the cached parent digest is not recomputed. The elaborated statements must then be equal. The serialization is not source text: post-order DAG, hash-consed, binder names erased, binder info kept, constants abstracted to a first-visit index list, Python `sha256(shape ‖ constants)`. [READ §3.1] Equality is that digest, not bytes of the `.lean` file. A lie on a `RENAMES` line is `rename not equal: NAME → NEW`. An unused line is `unused map line` (`drop the line`), so the map cannot rot by naming a declaration the diff does not touch.

`RESTATES: old → new` does not compare. The comment in §3.2 is "replaced by another declaration." There is no `restate not equal`. Check 1's rule is "absent, or a theorem whose statement differs, must be *named*," and the arrow is one of the names that satisfies it. Check 2's rule is "present as main has it, or declared in the map." The arrow satisfies that too. `foo → bar` with unrelated statements passes. Condition 1.

A meaning change is the other form, and it is the one E1 actually is. [READ `4916f3a`'s message; READ IMPACT-E1 §0] `selectHole_origin`'s conclusion now covers cells. Eight LiveHoles statements, and the `readsData`/`relReads` family, gained the binders `digestOf`/`look`. The message recorded this in prose and still said `PRICE PREMISES: none`. Same-name `RESTATES: name` is how that is declared: the statement is allowed to differ, and the line is the price. Absent the line, check 1 refuses `undeclared restatement: NAME`. A declared conjunct is not refused. That is right: the guard's job is to make the price a grep-able line, not to decide that the conjunct was uncalled for. The §4 default (direct parent diff, every restated theorem, not only ones a window commit touched) is what turns E1's prose into a checked list. Keep that default. The window alternative is the one that would have let those eight binders through unlabeled, because they are not "a recent commit's block went missing"; they are the landing's own statements changing.

`RESTATES: old → new` cannot do both jobs. If the arrow means "same statement, new name," it is `RENAMES` and the lie is caught. If it means "new meaning, new name," it is a `DELETES` plus a new declaration, and the meaning change is visible as a deletion rather than as a correspondence. One syntax for both is how the lie hides. Condition 1 does not remove the ability to change a meaning. It removes the ability to claim a correspondence you did not keep.
