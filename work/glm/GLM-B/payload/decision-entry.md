## KERNEL-79 · One wire name, one verdict: the reject table's three shared names renamed on the kernel side (2026-10-27; SPEC-DOCS kernel item 9; cv 01a17d72; GLM-B)

**Problem.** `Verdict.name` printed one string for two verdicts: `missingCell`, `rangeTooLong` and `duplicateRow` were wire names in both the receive-refusal and the reject tables, so a member reading a refusal record by name (`codeName` answers `refused NAME`) could not tell a recorded `rejected missingCell` from a recorded `refused missingCell`; only the code distinguished them, and nothing else did. Renamed on the REJECT side only — `Reject.missingCell` → `absentCell` (a touched cell the World does not hold), `Reject.rangeTooLong` → `rangeOverMost` (the kernel's `over*` bound idiom: overBound, overAllowance, overPrice, overTicks), `Reject.duplicateRow` → `duplicateRowSlot` (parallels `duplicateTouch`/`duplicateKey`; it fires on head and row slots alike) — keeping the law-7 invariant that a wire name is its constructor's, arguments dropped, and keeping the refusal names the rows and journeys already assert (`rows-rangeTooLong`, `refused missingCell` in LI). `Verdict.name_injective` (Kernel/Proofs/Refusals.lean) now states the check: one wire name determines one code, the two-table form of `Refusal.name_injective` and `Reject.name_injective`, decided over the two finite name tables that `codeName_code` ties to the constructors.

**Critique.** Codes keep their numbers (the renames are in place, no reorder) but `codeTable`'s text changes and `shapeStamp` with it, so a store stamped with the old table does not open under the new binary: the stamp is doing its job, and the next converge should say so if any probe still stamps the old table. Renaming the reject side moved the cost onto the kernel's own docstrings (Turn, World, Proofs) rather than member-facing rows, but the three names are one lane's coinage, not argued with the lanes that write rows; a cleaner design would have had the name carry its table from the start (`refused missingCell` against `rejected missingCell`), at the price of renaming every asserted string in the tree.
