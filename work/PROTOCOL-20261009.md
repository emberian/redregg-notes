## 1. One milestone, one measure
DEPLOYABLE-1 = THE BAR (cv 01a0f9c0-521b) on the public node. A sha S is DEPLOYABLE when, at S:
  (a) the static gate is red=0;
  (b) the standing journey run passes every REQUIRED row (list in MATURATION-MAP-20261009.md §3);
      UNCONFIGURED is allowed only for an input declared absent on that box, and a falling row count is a red (R3);
  (c) the BAR row measures BIRTHS: 1000 creates, write p99 ≤ 5 s, cold reopen ≤ 60 s (today's "growth" row measures updates; it is not the bar);
  (d) DEPLOY-3 ships S to dregg-workhorse and the public journey (two friends + hosted Hermes over ssh) passes there.
Nothing else is a goal until (d). Work that does not move a required row waits.

## 2. The dashboard is the status (R3, R9, f)
`work/DASHBOARD.md`, regenerated by `scripts/dashboard` from main's tip, results.tsv, the hub registry and cv. Five rows:
  1. BAR row at main: pass/fail, p99 write, reopen.   2. standing run at main: nonpass count AND row count.
  3. landed-to-main per Claude Mtok and per Codex weekly point.   4. oldest unanswered ASK / owed deliverable (min); main age (min).
  5. context per call by role; hub req/job (polling, narration).
No status prose anywhere. The root reports to Ember only on: a landing, a BAR change, a decision on the pause list, a blocker only Ember can clear.

## 3. Budgets, stated once a day (R5, R9)
Scarce: Claude tokens, Codex quota, Ember's attention. Boxes are cheap and should be loaded with compute-only filler (sweeps, benches, verdict runs).
The dashboard header carries the day's budget: max Claude agents, Codex points, and which windows are >70%. Above 70% of any window: no new Opus lane.
Codex spawns respect the pace gate unless Ember says otherwise, with the reason recorded.

## 4. Agents (R1, R2, h)
- root: decisions on the CLAUDE.md pause list, the dashboard, one source spot-check per landing. Renews from its own log at ~300K.
- ≤2 Claude deputies, one train each, capped at 200K, renewed from their own append-only event log (CXO-EXPERIMENT style). They brief, steer, read statements and diffs, verify plants. They never implement.
- ≤4 Codex workers per train (gpt-6.1-sol; astra for Lean). Every worker has a planted fault and an umbrella; the hub runs its journeys and cargo.
- scouts/reviewers on demand: fresh, ≤150K, one question, dead on reply. No Claude implementation lane, ever, above ~150K.
- Every agent is addressed by ROLE through one registry: the hub for Codex; `work/ROLES.txt` (role → current id) for Claude, written at spawn, resolved at send. A retired id is refused by the sender. A lane silent >2 h is a dashboard row, not "running".

## 5. A work item (R8, c)
(required row · the CURRENT red output of that row at the tip, pasted · target state · allow-globs · the planted fault · closes: <cv id>).
No brief without the current red run. Briefs paste real signatures and absolute paths. Items that touch a version counter or epoch are serialized by `cxo counter`, not by message. The deputy reads every new theorem STATEMENT before accepting a submit; a plant is observed red by the deputy, never cited from a commit message.

## 6. Landed means (c)
On GitHub main AND the standing run at that sha passes the required rows AND the cv task is closed by `Closes-Task:`. "Queued", "submitted", "green on train", "gate red=0" are states; reporting them as done is a protocol violation. The BAR row runs at every landing. The root pushes main only from a results.tsv it has read.

## 7. Tools never run from an installed copy (R4, d)
Runner, gate scripts, mk-lane, advance-base and the journey rows execute from the TIP'S TREE on the box, or print their sha and refuse when it differs from the tip. The hub installs only through drain → restart (jobs finished or cancelled first). `cxo version`, `runner --version` print shas; the dashboard shows drift. Session start checks: Codex CLI version, default model, hub sha, runner sha.

## 8. Surviving walls (R5, g)
Every agent appends to its event log as things happen; a kill at any instant leaves a continuation. The hub holds Codex state. A cron resumes agents BY ROLE after a wall. Long compute-only work is scheduled before a wall is likely.

## 9. The root never (f)
relays a first read as a finding (claims to Ember carry MEASURED/INFERRED, or come after a source check) · amends this file in flight · holds a deliverable a lane needs (hand it off or ticket it with an owner inside the hour) · runs a status census · pushes main on a static gate alone.
