Judgment
There are substantial constructions, but we have the same important failure mode
Ember described in fn: too much stops at independently working components while
the requested usable system is absent. It is inaccurate both to call this nothing
and to describe the remaining work as merely wiring. Missing semantics, protocol
properties, authority producers and coherent native execution are real work.

Effect of reducing about 30 agents to 15
Some real consolidation: scholars delivered bounded research; representation,
compiler optimization and capacity lanes finished specific useful packets; dependent
consumers stopped polling. We have no controlled before/after throughput measure,
so cannot claim a speedup caused by reducing headcount.
Actual cost: less parallel domain construction. FHE, Activity, money/DrEX, portable
homes, Station/fiction, and several UI consumers no longer had active builders.
Their responsibilities accumulated on World, runtime, receiver and root. A named
successor or retained callback did not give those people implementation capacity.
Build failures/import closure debt and the broad native interface remained serial
constraints. The cut did not create all of that debt, but made it easier to leave
unfinished domain work sitting behind it while reporting broad active coverage.
