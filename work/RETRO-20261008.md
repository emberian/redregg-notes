## The shape of the rewritten protocol (one page)

**Principle.** Scarce resources are **Claude tokens, Codex quota and Ember's attention**. Boxes are cheap.
Every rule below either caps one of the three or turns a document rule into a tool that refuses.

**The root does:**
- holds THE BAR and a ranked list of at most 5 outcomes, each with the exact row that proves it;
- makes decisions on the CLAUDE.md pause list;
- reads the outcome dashboard (below) on events;
- spot-checks one load-bearing referent per landing, in source.

**The root never:**
- relays a first read as a finding: claims go to Ember tagged M/I, or after a check;
- writes protocol amendments in-flight: a protocol change waits for the next generation, and one living file replaces the amendment stack;
- holds a deliverable a lane needs: it hands it off or makes it a ticket with an owner;
- runs at more than ~300K of context: it renews from its own log.

**Agents (steady state) [I]:**
- 1 root;
- **≤2 Claude deputies**, each owning one train, capped at 200K, renewed from their own append-only event log (CXO-3/4 style);
- **≤4 Codex workers per train**;
- 1 Claude integrator per box, short-lived per batch, not immortal;
- scouts and reviewers on demand: fresh, ≤150K, one question each, dead on reply;
- no Claude implementation lanes beyond ~150K context. Overflow means renewal, enforced by a tool that refuses.

**How work is defined.** An item is (outcome row, current red output pasted, target, allow-globs, plant).
No brief without the current red run at the tip. Items that touch a shared version counter are serialized by the tool
(a counter registry), not by message.

**What counts as landed.** On GitHub main **and** a standing run at that sha passes every required row
(UNCONFIGURED allowed only for a declared-absent input) **and** the cv task is closed by `Closes-Task:`.
"Queued", "green on train" and "submitted" are states, never reported as done.
The THE BAR row runs at every landing.

**Tools installed and kept fresh.** Nothing on a box runs from an installed copy. The runner, gate scripts and mk-lane execute **from the tip's tree**
(or check their own sha against the tip and refuse). The hub installs only through a blue-green restart that drains jobs first.
`cxo version` and `runner version` print shas, and the dashboard shows drift. Model and CLI versions are checked at session start.

**Ids and liveness.** Every agent is addressed by **role name** through one registry: the hub for Codex, and a role → current-id file for Claude
that every sender resolves at send time. Retired ids are refused by the sender. Waiters die with their agent.
A lane silent for more than 2 h is a dashboard row, not a "running" lane.

**Surviving usage walls.**
- Every agent appends events to its log as they happen, so a kill at any instant leaves a continuation.
- The hub holds Codex state.
- A cron resumes **by role** after a wall.
- At more than 70% of a 5-hour or weekly window, admit no new Opus lanes. Long compute-only work (sweeps, benches, upgrade trials) is the filler that costs no tokens.
- Codex spawns respect the pace gate unless Ember says otherwise for a stated reason.

**The 5 metrics to watch, all on one dashboard:**
1. **THE BAR row** at main's tip: pass/fail plus its numbers (write p99, reopen).
2. **Standing journeys at the tip:** nonpass count *and* row count (a falling row count is a red).
3. **Landed-to-main per Claude-Mtok**, and per Codex weekly point.
4. **Oldest unanswered ASK or owed deliverable** (minutes) and **main age** (minutes since the last landing with a non-empty queue).
5. **Context-per-call distribution:** lanes over 300K per call, tokens/call by role, and hub `req/job` (polling and narration).

## Signals that the SOFTWARE needs the architectural rethink (evidence, not design)

- **Version counters as the merge bottleneck [M].** Activity COMMAND went v4 → v12 in two days, seat frame v4 → v5, OUTCOME v4 → v5, checkpoint v1 → v4,
  StoreEpoch v5 → v6, the clock wire to v2. 4 of 5 ejections were two lanes taking the same counter.
  Every semantic change touches a hand-written frame codec and a global number.
- **Re-genesis is routine, not exceptional [M].** 66 of 378 commits mention a re-genesis, and 71 bump a version, epoch or refuse-by-name.
  Re-genesis is cheap by doctrine. The frequency still says the persisted shapes are not derived from one source.
- **A third of the commits are regenerated artifacts [M].** 108/330 are re-pins, ledgers and fixtures. One collector fix produced 17,469 redefined rows.
  The pin and ledger machinery measures *change*, not *meaning*, and humans admit it by attribution.
- **Two layers beside the kernel [M, OB-WORLD].** Not two admission models, as corrected, but an OB **invariant layer** (`Step` over `DataSnapshot`) and a **judgment layer**
  (laws, grants, domains, accounting) beside `World`. `HostRefinesWorld` names Objective 0 times. OB pins *absence*, which `World` could not express (`guardOnAbsent` refused).
  R2's `CheckedCommit` is the start of the join; it is not on main.
- **Θ(2ⁿ) encoders and O(h²) reads on the hot path [M].** `Nat.pair` in ObjectiveActivityReceiver, `TurnOfIntent.bytesCode`, `atPrefix` O(h²) (56.6 min at 30k).
  Per-create time is linear in cell count. Each was found only when THE BAR's row finally ran: performance is not in any model.
- **Installed copies and twins in infrastructure [M].** Box copies of runner, gate, hub and mk-lane diverged from the tree ≥4 times. Codex's default move is a twin
  (extractor, Bool beside `Failure`). That is the same class as the 11 Rust twins deleted earlier, now in tooling and fresh code.
- **Gates whose verdicts depend on who ran them [M].** The fixture was regenerated from the implementation it checks, until the authority landed. scripts-elab
  was red on any fresh lane because of row order. Product rows were UNCONFIGURED by environment. 214 mutants change no build verdict.
  The assurance surface is large and its *meaning* is not centrally defined.
