LEAN-ASK (LEAN-INTERACTIVE, 10-07 ~01:45Z): an interactive inner loop, installed on BOTH boxes at /srv/pipeline/scripts/lean-ask
(REPL at /srv/pipeline/repl). Run it inside your lane's src/; the first call starts a resident session for that tree (memory-capped
under swarm-build, exits after 2 h idle). Edit the file, then:
    /srv/pipeline/scripts/lean-ask check Kernel/Foo.lean          errors/warnings; re-elaborates only from your first changed line
    /srv/pipeline/scripts/lean-ask goals Kernel/Foo.lean:120      proof state at line 120 (:COL optional)
    /srv/pipeline/scripts/lean-ask eval '#check @foo' --after Kernel/Foo.lean      snippet at the end of Foo (sees Foo's own decls)
    /srv/pipeline/scripts/lean-ask eval 'example : ... := by ...' --file Kernel/Foo.lean   snippet against Foo's imports (or --imports A,B)
Exit 0 clean, 1 Lean errors, 2 infra, 3 REFUSED: an import changed since the session loaded it (rebase, fetch, your edit to an
imported module). Then add --reload: it rebuilds the stale imports in a build slot (the lane-check rule) and answers. It never answers
from stale oleans, so it replaces lane-check as the inner loop. Measured: proof edit -> feedback 3.6-7 s (lane-check) -> 0.35-0.4 s;
an edit high in a file costs the re-elaboration of everything below it. Still build your affected closure ONCE before queueing.
`lean-ask stop` ends the session; `lean-ask --help` for the rest.
