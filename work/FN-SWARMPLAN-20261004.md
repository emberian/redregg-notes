## 3. The contract (what stops the third repeat)

These are the rules the last two waves had on paper and did not run under. Each one names the failure it answers.

**Roles.** The plan was written for ≤7 agents; on 2026-10-04 ~00:30 ember asked for a megaswarm ("fan out some fable and opus subagents … taking up a LOT of the development strands … without being blocked on the current critical paths"), and it fanned out to 24 (roster with ids and code areas: `scratchpad/fn-briefs/ROSTER.md`). Width is safe only because the gate is intact and ownership is by code area: every lane owns named files; the four shared files (`host/interfaces.lisp`, `host/owner-host.lisp`, `host/native/owner.lisp`, `host/native/mux.lisp`) have a named owner per region and an announce-before-push rule; every lane is capped at one ACL2 process with REPLs on the laptop slot pool or persvati, and hbox carries only compose's certify and the integrator's image sets. One new role absorbs the merge volume:
- **Assembler** (Opus; long-lived; owns `next`): takes every READY, merges lane branches onto `next` with `--no-ff` (never cherry-picks), converges conflicts itself whenever the convergence is within reach — disjoint hunks, a renamed accessor, a moved include, a regenerated table, two added rows (ember, 10-04: "feel empowered to just do small local convergences if they are within reach … trying to preserve momentum") — and sends back only what needs the owner's judgment (a changed statement, two fixes to one function, anything that changes a theorem), runs the fast checks once per batch, keeps `build/coordinator/WAVE-STATE-20261004.md` (the roster, each lane's last READY, what is in `next`, reds — the one place the root reads), and hands the integrator one table per green batch. The integrator stays the only dev writer.

- **Integrator** (Opus; long-lived; `dev-serves`): the only writer to dev. Merges READY slices in batches; regenerates every generated file in the merge commit; runs the fast checks once per batch; builds one image set per batch of host-changing slices and publishes it; runs the 12 core natives on it. Never develops. Never cherry-picks a lane's commits by subject — merges them, so git keeps the provenance.
- **Composition lane** (Fable; wave 1 only): owns "the current source loads". One hbox REPL, the recipe, the 85 theorems, the 30 drifts. Reports a count every push.
- **Work lanes** (Opus; ≤4; each owns a code area, WIP 2): a lane finishes a slice to LANDED before the next. A lane that has waited 30 minutes on another lane or a box exits with its continuation written — it does not poll. In wave 0 two of the four are fixed: **HARVEST** (branches, worktrees, parked families → classified, gifts briefed) and **TESTING-SETUP** (one way to run each kind of test; stubs labelled; fast checks under 5 minutes).
- **Reader** (Opus; one): reads diffs and evidence; re-runs nothing unless the lane didn't run it; attacks the claim. Replaces the lieutenant/relay/liaison trio of the last wave.
- No lieutenants, no helpers-of-deputies, no horses. Sonnet only from a pool tagged Sonnet-suitable by the reader (the 10-03 pilots: ~40–60 items, not hundreds).

**The gate (answers: 751 pushes, no composition).** A slice is READY when, at its own sha merged onto current dev:
1. `tools/remote_check.sh auto` 13/13 (interface_emit `--check`, host_check `--books/--load`, ledger, reach `--strict`, build_lists, secrets, lock_discipline);
2. `tools/native_source_world.py` admits the slice's books into the current world **with zero deferrals** — a theorem that does not go through is a `proof-owed` ledger item naming the theorem, filed in the same push, and the slice is not READY until the integrator accepts that item explicitly;
3. `green_check --strict` owes nothing for the lane's changed closure (certified at current bytes; `farm.py submit --affected-by`);
4. for a host change: the defect's red-before/green-after native on the published set, run ids in the lanedump;
5. the report is the coordinate table (sha, world receipt, manifest id, image sha, native run id) and the LANEDUMP entry — no narrative status.
"Push before verify" (ember, 10-03 06:20) means *qualification* (the convergence checklist, rows 1–12) runs once at convergence; it never meant "no loading gate". The warm world is seconds to minutes; it is the gate.

**What a step is (unchanged from `how-we-work.md`, re-adopted verbatim).** DONE or NOT. DONE: the theorems over the host-called subject exist with teeth, the affected closure is green at current bytes, the behaviour is observed on an image, the evidence is filed. A step that needs a `partial` row is two steps. A branch someone else left is an input to a brief, never a thing to resume. Intermediate reds stay visible and never excuse a weaker statement or a host twin. The 10-03 "Short local loops" paragraph that softened this is withdrawn from `how-we-work.md` in wave 0.

**Replacement, not reverts (ember, 10-03 night: "extremely NOT in favor of doing ANY reverting or requiring full proofs before replacing old things. put in the new code, fix forward").**
- New code replaces old code in place; the old function and its theorems go in the same commit (a deleted theorem about a deleted function is not a deferral). Nothing is reverted to relieve a red.
- A replacement that bypasses a theorem the old route had — `fn-av-mca-read-span` over `fn-mca-read-span`'s `-keeps-funded` theorems, the de-cited `fn-owner-cat-may-seal` keystone — ships with a `proof-owed` ledger item naming the theorem to be written (PRF-1287 for the reader; a new prepare-transition keystone for may-seal — the old one was only a restatement), and the generated view shows the row `proved: no` until it exists. No merge is blocked on it; no claim is made without it.
- The gate (next paragraph) is about *loading*, not proving: the world must `ld`; what it refuses is a theorem still in a book that no longer goes through — exactly the signal that a replacement broke a neighbour.
- A fixture that stubs the function under test or a physical seam (`fnn-core`, `fnn-fault`, `fnn-store-close`, `fnn-heap-*`, `fnn-extent-*`; 47 today, 33 from the wave) carries `-mock` in its filename and is cited by no claim; the testing-setup lane (wave 0) decides which become real.
- A keystone citation is never removed to pass a gate; the gate's red is the finding, and the answer is the proof-owed item.

**Deferral (answers the hbox-only list of 94).** `--defer-defthm` is a development convenience whose list lives in the repo (`planning/world-deferrals.json`) and is counted red by the gate. The number on dev is 85 today; the wave-1 exit is 0; after that any nonzero number blocks the integrator's batch.

**Generated truth (answers "`--write` where `--check` failed").** The integrator regenerates `current.md`, `current-view.json`, `interfaces.json`, `interfaces-gaps.md`, `coverage.json`, `cost-*.json`, `repair/STATUS.md`, `proof-events.json` in every merge commit. A status document quotes a generated number with the sha it was generated at or not at all. `--write` output is never pasted into `now.md` as if it were `--check`.

**Boxes.** hbox for image sets, farm certify (≤16 jobs under `swarm-build`) and compose's REPL only; the laptop slot pool (six at 8 GB) is the default REPL host; persvati takes at most two fn REPLs swarm-wide (≤8 GB each; the Mini swarm's seats live there); `--box auto` for `farm.py submit --affected-by`; one ACL2 process per lane. The laptop cannot use hbox's certificates (the toolchain identity binds the SBCL runtime's content digest, `tools/acl2_toolchain.py`), so the laptop cache is warmed once under the laptop identity (lane LAPTOP-WARM, 10-04). The fn node on hbox is not restarted by any lane; the redeploy runs through breadstuffs-89 on ember's word.

**Cadence (answers 105 check-ins → 492 messages).** The integrator posts the coordinate table when a batch lands or a gate goes red; lanes post at READY or at exit. ember's directives are recorded in `planning/decisions.md` the same hour, with scope ("push before verify = qualification once at convergence; the loading gate stands"). After a compaction a lane's first line is the three files it re-read (its brief, its lanedump, `now.md` §coordinates); the root's is `cv prompts` of ember's last twenty prompts.

**Evidence.** Filed, not committed (`evidence_store.py put`); the index line is the claim. Nothing credential-shaped in a ledger item (`secrets_check` runs in the gate).
