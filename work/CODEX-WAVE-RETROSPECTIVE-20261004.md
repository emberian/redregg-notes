## F. Rules for a lane protocol
1. A capability row changes state only by an artifact a non-author re-ran from main. "integrated" = on the default branch, built from a fresh clone, a gate can go red on it. Lane-local checks, mixed/symlinked closures, "PASS per owner" = authored or lane-checked only. A tip that does not build from a fresh clone blocks every "integrated".
2. Every regression test and proof a lane writes lands in a default gate in the same commit, or the row says NOT-GATED by name.
3. When an operation is uncertain, the next step is reading the evidence, not another attempt: after the second failed retry, a read-only diagnosis of existing journals/logs is mandatory. "Uncertain" for more than an hour is a finding, not a state.
4. Every lane dir has a top-level STATUS naming its newest passing log; superseded logs marked; plain sentences, one fact per line; the root rejects any status it cannot parse cold.
5. Every lane has a named consumer; output names a consumer on main within N hours or the lane is serialized. Breadth (lanes running, commits pushed) never counts as progress; progress = one end-to-end join reaching further.
