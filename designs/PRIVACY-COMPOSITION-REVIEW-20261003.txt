2. THREAT MODEL / REPROFILES

P0 Scheduled PSK RPC: honest client and server, owner-private durable files,
external network observation and manipulation. AEAD integrity and fixed cell
shape are the claimed properties. Source IP, endpoint, connection presence and
public faults remain visible. Native server sees signed graph/author. Neither
source anonymity nor forward secrecy/full PQ stack is claimed.

P1 Restricted registered cohort mix: fixed public cohort, at least two honest
clients, three independent mixers plus separate honest receiver, at least one
honest whole-batch shuffle over ALL protected epochs, additional honest
NONCOLLUDING registrar, authenticated confidential slot enrollment and route
commitment upload, trusted local durability, static corruption/no later secret or
pairing disclosure, and bounded processing before public release. Registrar sees
the paired stage hashes; it can map packets if it colludes. Native receiver sees
ordinary signatures and authored graph. Public cohort/presence/failure/capacity,
key inventory, epoch schedule, route endpoints and broadcast audience are allowed.
This is a real extra trust assumption relative to one-honest-mix claims. It is
neither inherited Outfox security nor a fully PQ OO/agreement deployment.

P2 Physical correlations / ASKS: n=3f+1 (implementation n<=16), static cumulative
f corrupted parties, authenticated confidential sender channels, eventual honest
delivery, honest crash-storage authority and separately controlled monotonic
correlation anchor. Dealer may be one corrupted party. The local Unix anchor test
is IO evidence, not separate rollback authority. ASKS malicious-dealer default
semantics are allowed; completed sharing must still retain reconstruction support.
This source is not ACS/AMPC or prior-state VSS. Detailed capacity/retention errors
are currently private host diagnostics, not admitted strong-world public outputs.

P3 Bend reference: clear source AST/data, exact Eval/Walk evidence, finite ticks
and exact source Trace. No secrecy property is established by executing it.
Oblivious Boolean heap DAGs describe a fixed public schedule; their clear checker
is conformance machinery. Secret-PC/closure controller lowering and malicious
shared-wire execution remain receiving work. Do not silently instantiate P3 as
the backend of a P2 committee-private contract.

P4 First FHE slice: public fixed finite Bool program, private canonical input,
real ciphertext evaluation, public independent ciphertext reexecution for
integrity, owner-authorized private result release. This is the design's first
construction, not an already joined admission path. Public output of negation
would intentionally reveal the input; confidentiality must be stated relative to
the permitted output. Program secrecy, threshold DKG/relin correctness and
persistent encrypted-state release are distinct stronger constructions.

None of the findings below assumes compromise of the honest registrar/receiver,
later key disclosure in P1, or more than f corrupted parties in P2. Lifetime
failures excluded by P1 are recorded as qualification limits, not in-budget
attacks. These profiles do not lower the full private-world destination.

3. CONFIRMED FAILURE: ASKS SUPPORTING SHARE OVERWRITE

Consumer: native/private-backend/src/asks.rs, original PrivateShare arm lines
279-288; progress lines 300-315; start_reconstruction's local_share broadcast.
Original rule replaced private_share on every validly shaped dealer message until
sharing output terminated. private_valid triggered RA but retained no immutable
copy of the share that justified that acknowledgement.

Minimal in-budget source trace, n=4,f=1, party0 malicious dealer:
  A. Dealer creates a coherent commitment vector and matching private shares.
     Deliver commitment RBC until honest1,2,3 have the vector.
  B. Deliver their matching private shares. Each honest node emits RA Echo(1).
     Hold all resulting RA traffic in the network scheduler.
  C. Dealer sends wrong replacement coordinates to each honest node. The old
     PrivateShare arm overwrites each commitment-matching private_share.
  D. Deliver the previously generated RA Echo/Ready traffic. Three honest Echoes
     suffice for Ready; agreement completes at all honest parties.
  E. Every honest SharingOutput.local_share is None. Their start_reconstruction
     emits no Reconstruct shares. The sole malicious dealer withholds.
Completed sharing therefore has no honest reconstruction support. This is a
totality/recovery failure, not a claim that the dealer learned honest secrets.
It matters to key/output custody: a completed token cannot justify recoverability
merely because RA terminated and numerical holder counts look sufficient.

Repair: retain the commitment-matching accepted_share BEFORE RA Echo is emitted;
never let later replacements erase it. Continue accepting candidates before a
commitment is known, but freeze the first verified share supporting acknowledgement.
Use the retained share when constructing SharingOutput. Reordered commit/share
arrival and replay must preserve this rule.
