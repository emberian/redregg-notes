JUDGMENT
The recovered consumer is a continuing collaborator with appropriate context,
private notes, actual tools and participation across sessions and rooms. It is
not adequately specified by a durable completion receipt, a game NPC/GM, a
model-name badge, or a portable applet counter. The complementary human
consumer is an actuable, spatially persistent technical desktop: documents,
objects, methods, permissions, history and tools have direct operation surfaces.
These consumers can share source/history/authority without one conversation UI
or one compulsory fiction metaphor.

There is a concrete Mini/Bend seam: a bounded source-defined context projection
over canonical signed activity and authored documents, with immutable evidence,
current placement/text/authority, pinned summary inputs and invocation identity
kept distinct. Mini's current resident request/completion machinery is the
receiving home; Allgame contributes lived requirements and projection patterns,
not another runtime or credential model. Bend can author/check/execute the
deterministic selector and contextual work rules, but the physical observation,
authorization, provider call, retained output and current release still belong
to actual Mini controllers. A context selector cannot grant itself a read.

ALLGAME: WHAT REALLY EXISTS, WHAT STILL LOSES CURRENT CONTEXT
Root /Users/ember/dev/allgame. Read README and actual claude_resident modules:
edits, state, prompt, resident, sessions, handled, distill; sampled GLM's
backend/Discord adapters. These are source reads, no live service inspection.

1. Original event history and selected context already differ.
state.py:269 log_message appends foreverlogs. Content edits append sidecar
records (313); load_edits434 folds newest content, _apply_edit138 annotates it.
Multiple recent-topic/stream/log renderers use the fold. Current LoadBound60
and context_floor/context_quarantine now exist: floor excludes raw history
while allowing it into distilled memory; quarantine excludes selected spans
from both. Neither deletes original logs. The dated 'quarantine absent' claim
in the Aug23 assistant exchange is superseded by source. Separate storage,
current content and context load policy is a useful transferable design.

2. Moves are retained evidence, not correct room placement.
edits.py:97 patches pending/inflight dict content;123–137 logs destination only
and explicitly says topic logs do not follow moves. state.py:323 appends a
move record without content, and load_edits ignores it. msg_index is not
updated to destination in this handler. For a moved, not-yet-answered batch,
the handler does not relocate its stream/topic or de-queue/re-dispatch it.
This establishes the local implementation boundary; it does not prove every
live trigger in the entire service misroutes. Current-room projection needs
placement semantics, not just an audit annotation saying 'moved'.

3. Warm inference context and distilled memory are separate stale consumers.
resident.py:342–382 retrieves per-topic session and reuses system_blocks;
fingerprint_state in prompt.py:497 hashes identity/scratchpad/inbox, selected
Allgame files, cross-topic board/postmark/journal/person notes. It does not
fingerprint topic edit/move sidecars or topic hit revisions. update handler623
passes pending/inflight batches, not already-retained session messages/SDK
context. Thus fresh renderer correctness is not a warm-context invalidation
mechanism. During a running provider call, mutating a Python dict cannot
retract already-sent text; next-turn correction or a new context lineage needs
an explicit policy.
distill.py:235 reads raw jsonl and builds text directly from m.content at282,
without load_edits or move fold. It advances a line-count cursor and seals eras
at108–124; old edits/moves do not dirty already-sealed inputs automatically.
Current cold view may be corrected while its memory summary still remembers
superseded text in the old room. Summaries are readings with provenance, not
canonical source. They need input dependency/version pins and invalidation or
visible historical status; merely increasing the raw budget does not fix this.

4. Persistence does not certify exact physical handling or continuity.
HandledSet is bounded50k IDs and appends immediately, but mark mutates memory
before append and only logs persistence failure. SessionManager TTL/LRU parks
ended in-memory sessions for summaries; permanent/SDK bindings and private
state contribute other continuity mechanisms, not process RAM migration.
Do not port cap-eviction assumptions as a proof of indefinite replay safety.
GLM ChatBackend intentionally shares outbound/history operations while keeping
different inbound platform loops; platform room prefixes preserve distinct
contexts. This is useful interface factoring. Its normalized identity/history
is platform trust, not a Mini signature or permission to publish model data.
Current send/reaction tool defaults consume the actual event cursor; they
should be reused as interaction behavior, not reported absent.

observations, retaining references to immutable activity identity and revisions.
Inputs: declared room/topic/assignment, requested cursor/coverage, viewer's
already-authorized source projection, current content+placement revisions,

Bend authors deterministic selection/work reaction/summarization acceptance
rules and exact typed effects, preferably via the same object methods/views.
External model-generated summary is proposed authored data with citations,
not deterministic Bend truth; acceptance/revision/current source eligibility
are governed methods. Generate shared projection/codec/intent adapters for web,
native and resident consumers. Check relation to canonical Mini state; do not
blindly run the upstream C/JS compiler as an authority interpreter. Current
BendTT proofs do not prove those compilers or physical IO refinement.

Persistent continuation is a typed closure, not one opaque OS backup: exact
source/modules and evaluator profile; authorized resource references; immutable
history/current revision; private notes/summary input pins; pending operation,
provider result/outbox and delivery obligations; audience/release generation;
available body/tool ports; selected context policy; explicit host/identity key
custody and successor fencing. Some bytes are unavailable after revocation,
some physical effects already happened, and an external provider session may
not migrate. Preserve those distinctions. A historical reference can show a
past allowed view, but current inference/release needs its declared policy.

PRECISE QUESTIONS AND CHEAP FALSIFYING TRACES FOR OWNERS
1. Context currentness: append A, edit A before queue selection, then after
   selection but before dispatch, then during provider call. One stable event
   ID with distinct source revisions; already-started exact work cannot be
   silently reauthored. UI and next inference show selected/current revision.
   Owner seam: canonical message/domain contract + resident_requests;
   acceptance policy still to specify, not a required human permission barrier.
2. Placement: move an addressed message from roomX toY before reply, with
   different grants/audience. X current projection excludes/relabels it;
   Y includes only under Y authorization. Original author/history remains.
   A move cannot launder X private bytes into Y or create new effect identity.
3. Warm/cold equivalence: same authorized history/revisions/load policy yields
   same selected semantic context after restart or warm cache. Summary produced
   before edit/move stays visibly historical or is regenerated; quarantine must
   not re-enter through summary. Pure Bend selector is a good narrow test home.
4. Current authority: revoke author's request eligibility, resident read grant
   or output audience separately. Unstarted tasks cancel/refuse; uncertain
   started tasks retain recovery evidence; retained result does not imply current
   disclosure. Historical author identity survives. Feed roster is not a cap.
5. Input identity: unrelated provider height/budget movement creates no new
   assignment; actual role/source/placement/load-policy revision does. Preserve
   existing height-normalization without stripping revision/payload roots.
6. Canonical receipt: driver cut after source end_turn, loss of delivery reply,
   changed rendered excerpt and controller restart must recover same operation,
   selected input revision and installed output, no second charge/dispatch.
   Extend current useful-work receiving fixture; don't replace its frozen input.
7. Portable refs: replay old epoch descriptor after reconnect/rebind, substitute
   peer key for same cell, omit program/dependency/source bytes, export raw host
   signing seed, revoke old host after successor, and retry old pending intent.
   Separate reference validity, identity authenticity, execution, availability,
   custody and current permission. Drorb/Bread leaf tests are donors, not proof
   the complete physical Mini bridge exists.
8. Real resident actuation: continuing model reads/cites current source, performs
   one permitted tool/document effect, verifies readback, can decline/socially
   participate, and carries useful chosen notes into a later context. A fixed
   provider fixture, LocalBrain script, NPC GM or counter applet may qualify
   pieces but cannot alone satisfy that experience. Technical direct desktop
   surfaces must actuate the same objects and show current operation outcomes.
